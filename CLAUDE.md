# CLAUDE.md – сайт «Учимся работать с Claude»

Главный документ проекта. Исходник – ТЗ v1 от 16.11.2026 (Proton Drive: `ДРУГИЕ/Обучение Claude/результаты/2026-11-16_ТЗ_сайт_обучения_Claude_Code_v1.md`). При расхождении действует этот файл.

## Цель

Закрытый сайт, на котором четыре друга владельца учатся работать с Claude: 26 уроков в четырёх блоках по порядку, тест после каждого урока, практическое задание. Владелец видит прогресс каждого и проверяет задания.

Аудитория (допущение): взрослые, с Claude почти не работали, учатся для работы и личных задач, язык русский. Тариф участников – Pro (нужен для уроков 6–8; для Free в этих уроках пометка, что доступно не всё).

## Стек и размещение

- Vite + React + TypeScript, статический сайт на GitHub Pages: `https://cryptodrakaris.github.io/claude-school/` (`base` в `vite.config.ts`).
- Маршрутизация через хэш: `#/`, `#/lesson/1`, `#/admin`, `#/profile` (`src/lib/router.ts`).
- Supabase (бесплатный тариф): Auth (magic link), Postgres, RLS. Клиент – `src/lib/supabase.ts`.
- Деплой: GitHub Actions → Pages при пуше в `main` (`.github/workflows/deploy.yml`).
- Репозиторий публичный: в нём нет ответов на тесты и секретных ключей.
- Уроки – Markdown в `content/lessons/NN-slug/`, не в базе.

## Структура

```
src/                 код сайта (pages/, lib/)
content/lessons/     NN-slug/{lesson.md, practice.md, quiz.json, homework.md}
supabase/migrations/ миграции SQL
supabase/seed/       quiz_keys.sql – в .gitignore, грузится npm run seed:keys
scripts/             check-typo.mjs, check-secrets.mjs, seed и тест RLS
tests/               тест RLS
```

## Роли и вход

- Роли `student` и `admin` (поле `profiles.role`). Вход по ссылке из письма, без паролей.
- Самостоятельная регистрация выключена; участников приглашает владелец (Supabase → Authentication → Invite user). Профиль создаётся триггером, роль по умолчанию `student`; `admin` ставится вручную SQL-запросом.
- Supabase Auth: Site URL и Redirect URLs = адрес на GitHub Pages и `http://localhost:5173`.

## Страницы

1. Вход: почта, «Получить ссылку для входа», «Проверьте почту».
2. Программа: 8 карточек со статусом (закрыт / открыт / тест сдан / задание сдано / задание принято), полоса прогресса. Урок 1 открыт сразу, урок N+1 – после теста N на 6 из 8 или ручного открытия.
3. Урок: теория → практика → тест (8 вопросов, один верный, разбор после отправки, пересдача без ограничений, в зачёт лучший результат) → задание (ссылка + комментарий, статус и комментарий владельца, пересдача при «на доработку»).
4. Панель владельца: таблица «участник × урок» (лучший балл, попытки, статус задания, последняя активность; отстающие цветом: два теста подряд ниже порога или задание не сдано больше 7 дней после открытия урока); очередь заданий (оценка 0–6 = три критерия по 0–2: задача решена, запрос поставлен грамотно, результат проверен; статус; комментарий); ручное открытие урока.
5. Профиль: имя (вводится при первом входе), выход.

Все страницы: работают с телефона, контраст не ниже WCAG AA, всё доступно с клавиатуры, спокойное оформление без шаблонной «AI-эстетики». Перед сдачей этапа 6 – скил design-audit.

## Данные (Supabase)

Таблицы `profiles`, `quiz_keys`, `quiz_attempts`, `homework`, `lesson_unlocks` (набросок – в ТЗ, раздел 5). Функция `is_admin()` (security definer). Проверка теста – только на сервере: RPC `submit_quiz(p_lesson_id, p_answers)` сверяет с `quiz_keys`, пишет попытку, возвращает балл, `passed` и разбор. Сводка для панели владельца – представление или RPC.

RLS на всех таблицах:
- `profiles`: участник читает и правит своё имя (не роль); владелец читает все.
- `quiz_keys`: закрыта всем, кроме владельца.
- `quiz_attempts`: участник читает свои; вставка только через `submit_quiz`; владелец читает все.
- `homework`: участник вставляет и читает свои, правит только `link` и `comment` и только в статусе `needs_rework`; владелец читает все и правит поля проверки.
- `lesson_unlocks`: участник читает свои; владелец пишет.

Реализация – `supabase/migrations/20261116000001_init.sql`. Отличия от наброска ТЗ: одно задание на участника и урок (`unique`), пересдача – правка той же записи; защиту полей задания держит триггер `homework_guard`; роль защищена колоночным правом (участнику доступно только `update (full_name)`); RPC `my_progress()` и `admin_progress()` считают статусы, дату открытия урока и признак отставания через общую `_progress(uuid)`. Миграции применяются вручную в SQL Editor, новые – отдельными файлами по порядку.

Две проверки RLS:
- `npm run test:sql` – локально на PGlite с заглушкой `auth`, без сети; идёт в CI.
- `npm run test:rls` – на живой базе: создаёт двух временных участников, под учёткой A пытается прочитать чужие попытки, ключи и задания, ждёт отказа, удаляет учётки. Нужен ключ service role в `.env`.

## Безопасность

- В клиенте только anon-ключ (`VITE_*`). Ключ service role – только в локальном `.env` и без префикса `VITE_`.
- Перед каждым коммитом: `npm run check:secrets` (ищет ключи, JWT, `.env`, `quiz_keys.sql` в индексе git).
- Личные данные участников – только почта и имя.

## Язык и типографика

- Весь текст сайта и уроков – русский, обращение на «вы», без канцелярита и рекламы.
- Тире только среднее (–); длинное (U+2014) запрещено везде. Кавычки «ёлочки»; прямые кавычки в русском тексте запрещены (в коде – по синтаксису).
- `npm run check:typo` проверяет `content/` и строки интерфейса в `src/`; CI падает при находке.
